# Excalidraw palettes

Palettes are generated by home-config's `theme-builder` skill from the installed
Doric package. Home Manager's Emacs feature installs this directory at
`~/.config/excali/` (or `$XDG_CONFIG_HOME/excali/`). Read
`palettes/<theme>.json` before creating or deliberately restyling a diagram.
All 26 Doric themes have a palette; the JSON is data, not executable code.

## Editor use

In excali-mode's native styling transient, choose **p — Palette: …**, then:

| Preset | Intended use | Doric source |
| --- | --- | --- |
| Default | Arrows, text and unfilled shapes | `default` foreground; transparent fill |
| Neutral | Ordinary filled boxes, such as service participants | `highlight` background, inherited `default` foreground |
| Accented | Highlighted boxes, such as a human participant | Paired `region` background/foreground |
| Muted | Secondary boundaries and lifelines | `shadow` foreground; transparent fill |
| Red, Green, Yellow, Blue, Magenta, Cyan | Meaningful diagram-specific categories or emphasis | Doric's corresponding `fg-COLOUR` / `bg-COLOUR` pair |

The six named colours are additional presets in the same palette menu (keys
`r`, `g`, `y`, `b`, `M`, `c`). They use each theme's own colours, not fixed hex
values. Their names do not assign semantics: Green does not automatically mean
success, for example. Choose and label meanings appropriate to the diagram.

Each preset contains `stroke`, `fill`, and `text` colours. Applying a preset
changes selected elements and their bound labels, and sets native defaults for
new ordinary shapes, lines, arrows and text. With no selection, only defaults
change. It sets solid fill but preserves geometry, line patterns, fonts,
opacity, and unrelated metadata.
Sticky notes and their labels are excluded from palette presets, including
when selected together with ordinary elements. Use the native colour pickers
for them. Note creation and label entry stay native, without our text-contrast
correction; native current-item defaults can still influence note text as usual.
Presets always set the defaults for ordinary drawing elements, even when the
selection contains only excluded notes.
Existing standalone text changes only when selected. Text uses the preset's
foreground when readable against its actual background; otherwise black or
white is used for contrast. Transparent containers and arrow labels use the
canvas, not the preset's box fill. Explicit native colour/fill overrides end
the active creation preset and continue to work normally.

The native colour pickers are unchanged. `M-x my/excali-use-preset` provides the
same preset actions outside the transient. Every explicit preset application
reads the **current Emacs theme's** palette; individual presets have no separate
Doric-theme chooser.
To style an existing element, select it, open the styling transient with
`M-x excali-style`, press `p`, then choose a preset. Its bound label is included;
unselected elements and the canvas remain unchanged.

The main menu recognises only the explicitly selected elements' actual palette
styling; it does not add a box's unselected label to the selection. A Neutral
box can therefore show Neutral even if its label has different ink. Selecting
both the box and that label shows Mixed. Applying a preset still styles the
box and its bound label together, as described above.
With no selection, the menu recognises the native
current-item defaults instead. It shows **Palette: Neutral**, for example,
**Mixed** for differing styles, or **Custom** when the styling matches no preset.
This works after saving/reopening because it compares colour/fill properties,
not the last preset command or stored roles. Where the properties cannot
distinguish multiple presets (such as standalone text with shared ink), it
uses a bound label's container to disambiguate where possible, then prefers
the first matching preset in the table above. A label can still match a
different preset from its parent. Equivalent native hex colours are normalised
before comparing styles. A common matching preset
across the selection takes priority over differences between shape and label
properties that do not apply to both.

Recognition is read-only, uses the current Emacs theme's palette, and never
changes colours, defaults, undo/redo or metadata. After a theme change, old
colours may show Custom until deliberately restyled; they are not recoloured.

An applied creation preset keeps its own colour snapshot until another preset
or native override is applied; changing the Emacs theme does not change that
snapshot, its text-contrast behaviour, or existing elements. Recognition alone
does not activate this creation behaviour. The active creation preset is
buffer-local, not saved role metadata: native current-item defaults persist,
but after reopening, reapply a preset to enable its contrast-aware text creation.
To change just the canvas, use `my/excali-set-canvas-background`; its interactive
default is the current Emacs theme's background.

New drawings start with the active theme's palette canvas and Default style.
If that theme has no installed palette, they retain the original one-time
initialization from the theme's default background/foreground, without palette
provenance. Existing native/PNG/SVG scenes retain their saved colours and
defaults. Themes and auto-dark never recolour a drawing. Initial palette metadata
is provenance only: it does not override the current theme for later explicit
preset applications. If the current theme has no installed palette, explicit
preset application reports an error without changing the drawing.

## Explicit diagram conversion

Run **`M-x my/excali-update-palette`** in a diagram buffer, then choose an installed
Doric palette to update that entire diagram. Completion requests alphabetical
order, with the current Emacs theme as the default when its palette is installed;
press `RET` to accept it. Vertico pins the default above the otherwise alphabetical
list. Input starts empty so you can browse or filter all palettes. If the current
theme has no installed palette, choose one explicitly.
The picker uses the same `theme` completion category as `consult-theme`, so
Marginalia shows its standard theme descriptions. With the configured Orderless
completion, type `&dark` or `&light` to filter by those annotations rather than
the palette names.

The highlighted palette previews **automatically as you move through or filter
candidates**, like `consult-theme`; no preview key is needed. Each preview starts
from the original scene, not the previous preview. Frame and minibuffer resizing
keep showing the selected preview. Press **`C-g`** to cancel: the original colours,
canvas, drawing defaults, active creation preset, metadata, modified flag,
selection and undo/redo history
are restored. Press **`RET`** to accept the selected palette: one normal conversion
is applied to the original scene.
Preview edits do not enter native history. The accepted conversion retains the
non-element undo boundary below. This does not preview or enable any Emacs theme.
Preview is render-only: editing, saving and history commands never operate on a
disposable preview scene. Large drawings may take longer to convert and redraw
when the highlighted candidate changes.
The Emacs theme itself never changes. There is no transient entry, automatic
theme-change hook, or operation across other diagram buffers. The selection does
not restrict conversion. Save normally when satisfied.

Lisp callers can pass a palette name, e.g.
`(my/excali-update-palette "doric-obsidian")`; a call without an argument continues
to use the current Emacs theme's palette without prompting.

The command recognises presets using the saved `currentPalette` snapshot, or
`initialPalette` before the first conversion. It converts matching shapes,
arrows, standalone text and bound labels, resolving label contrast against the
converted parent and canvas. Matching canvas colour and drawing defaults are
converted too; an already active creation preset receives the converted colour
snapshot. Conversion does not activate a creation preset after reopening.

Solid borderless rectangles whose fill matches the source palette's canvas
also follow a matching canvas conversion. This supports separate label
backplates: their transparent stroke stays transparent and only their fill
changes. It applies to all rectangles with that styling, not just those near
text; without roles an intentional same-colour rectangle is indistinguishable.
Patterned, custom-filled or non-rectangular shapes are not backplates. If the
canvas is custom and preserved, backplates are preserved too.

Older version-1 snapshots containing only Default/Neutral/Accented/Muted remain
valid conversion sources. The six named presets are optional in saved snapshots;
new generated palettes include all ten presets.
Applying a named preset missing from a saved snapshot extends `currentPalette`
with that preset only when its theme, canvas and every existing preset value
match the installed palette. Initial provenance remains untouched. This lets
legacy diagrams use new colours and convert them later, including after reopening.
Incompatible or missing provenance is not repaired by applying a preset; those
colours remain custom/unmatched unless the saved source already recognises them.
When a legacy target lacks a needed named preset, affected elements and drawing
defaults stay unchanged rather than receiving guessed or invalid colours.

Custom/unmatched styling, sticky notes and their labels, deleted elements,
geometry, fill patterns, fonts, opacity and unrelated metadata remain unchanged.
A custom canvas or custom drawing defaults are preserved. Without per-element
roles, identical source styling can imply several presets: parent context helps
disambiguate labels, but if matching roles would produce different target colours,
the element is left unchanged. The command reports updated elements and ambiguous
or unsupported matches. Unmatched elements are not counted in that report.

Missing/invalid palette provenance or an unavailable/invalid target palette stops
conversion without edits. Native browser exports that lost provenance therefore
cannot be converted by this command. Use individual preset commands instead.

Initial provenance stays immutable. A successful conversion stores a complete
target palette snapshot as `homeConfigPalette.currentPalette`, preserving other
metadata. This becomes the source for the next conversion, including after
save/reopen; unmatched or ambiguous elements are not assigned persistent roles.
As with menu recognition, manually chosen colours indistinguishable from a preset
are recognised as that preset.

**Undo boundary:** converted elements form one native undo step. Canvas, drawing
defaults, the active creation preset and palette snapshots are not part of native
element history. Undo therefore does not restore the whole document or its source
palette. Redo an undone conversion before converting again, or reopen the last
saved document. No upstream history patches are installed.

## Agent use and JSON

Keep `.excalidraw` JSON authoritative. Copy `canvas` to
`appState.viewBackgroundColor`. Map preset `stroke` to `strokeColor`, `fill` to
`backgroundColor`, and use `fillStyle: "solid"` for filled shapes. Set label
elements' `strokeColor` from the paired `text`, checking it against the fill
actually behind the label. Standalone text and arrow labels sit on the canvas.
Do not use a box's text/fill pair blindly for those labels. New-item defaults
can be stored as `appState.currentItemStrokeColor`,
`currentItemBackgroundColor` and `currentItemFillStyle` in native files.

### Constructing theme-portable diagrams

- Prefer native bound labels where appropriate. Set the text's `containerId`
  and the container's reciprocal `boundElements` entry so the editor knows the
  label's background. Merely positioning text over a box does not bind it;
  conversion treats unbound text as sitting on the canvas, not the box fill.
- When separate label backplates are needed, use rectangles with
  `strokeColor: "transparent"`, `fillStyle: "solid"`, and `backgroundColor`
  copied from the palette's `canvas`. These follow explicit palette conversion
  as described above. Do not invent a near-canvas shade. Unbound text over these
  backplates uses the canvas text-contrast rule.
- Use named colour presets for meaningful distinctions, not decoration, and
  keep their meaning consistent within a diagram. Read the selected theme's
  palette; do not substitute fixed hex values or hand-mixed shades. Use the
  stroke/fill/text triple together for filled boxes, with text contrast checked
  against the actual fill. Standalone and arrow labels require a canvas check,
  including when using named colours. Use the same 4.5:1 contrast threshold as
  the editor, falling back to black or white when the preferred ink fails.
- Never make colour the only distinction: retain descriptive labels or another
  visual cue, such as a meaningful line pattern.
- Before handing off a generated diagram, verify explicit conversion to at
  least one light and one dark palette on a disposable copy. Check labels,
  backplates and canvas together, not only box fills. Preserve the original
  diagram and initial provenance; disclose any ambiguous/unconverted styling.

For a new drawing, ask which theme to use if it was not supplied; do not assume
the user's current theme from a palette filename or yesterday's drawing.
The example image-rollout diagram originally used hand-picked fills, not this
generated palette. Its service boxes correspond to Neutral, Mitch's boxes to
Accented, messages/headings to Default, and lifelines/phase boundaries to Muted.
Generated Doric Earth colours intentionally differ from that demo.

New editor-created drawings record this top-level provenance:

```json
"homeConfigPalette": {
  "version": 1,
  "initialTheme": "doric-earth",
  "initialPalette": { "version": 1, "theme": "doric-earth", "canvas": "…", "presets": "…" }
}
```

`initialPalette` contains the complete palette JSON object, not the illustrative
ellipsis above. Agents creating new diagrams should write the same record.
It is an immutable creation snapshot, not a current-role declaration; later
manual edits and preset applications do not update `initialPalette`. A compatible
legacy `currentPalette` may be extended as described above. Preserve unrelated fields,
including element `customData`. No per-element roles are recorded.

The pinned excali-mode preserves this metadata and native current-item defaults
through save/reopen. **Browser Excalidraw exports discard the top-level metadata
and current-item defaults**, but preserve the painted colours and canvas.
Where the diagrams directory is version-controlled, missing initial provenance
may be recovered from Git history. Do not create commits automatically.

For an agent-side theme conversion, use `currentPalette` when present, otherwise
the stored initial snapshot, as the source and a generated JSON file as the
target. Without roles, equal colours can be
ambiguous: consider element types, fill/stroke combinations and bound-label
relationships, preserve unmatched/explicit colours, and ask about ambiguities.
Review the diff before replacing a drawing. Preserve initial provenance and
record the target snapshot in `currentPalette` after conversion. The editor
command above provides explicit conversion; automatic theme following is not
provided.
