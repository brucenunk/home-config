# Excalidraw palettes

Palettes are generated by home-config's `theme-builder` skill from the installed
Doric package. Home Manager's Emacs feature installs this directory at
`~/.config/excali/` (or `$XDG_CONFIG_HOME/excali/`). Read
`palettes/<theme>.json` before creating or deliberately restyling a diagram.
All 26 Doric themes have a palette; the JSON is data, not executable code.

## Editor use

In excali-mode's native styling transient, choose **P — Palette…**, then:

| Preset | Intended use | Doric source |
| --- | --- | --- |
| Default | Arrows, text and unfilled shapes | `default` foreground; transparent fill |
| Neutral | Ordinary filled boxes, such as service participants | `highlight` background, inherited `default` foreground |
| Accented | Highlighted boxes, such as a human participant | Paired `region` background/foreground |
| Muted | Secondary boundaries and lifelines | `shadow` foreground; transparent fill |

Each preset contains `stroke`, `fill`, and `text` colours. Applying a preset
changes selected elements and their bound labels, and sets native defaults for
new ordinary shapes, lines, arrows and text. With no selection, only defaults
change. It sets solid fill but preserves geometry, line patterns, fonts,
opacity, and unrelated metadata.
Sticky notes and their labels are excluded from palette presets, including
when selected together with ordinary elements. Use the native colour pickers
for them. Note creation and label entry stay native, without our text-contrast
correction; native current-item defaults can still influence note text as usual.
Presets always set the defaults for ordinary drawing elements, even when the
selection contains only excluded notes.
Existing standalone text changes only when selected. Text uses the preset's
foreground when readable against its actual background; otherwise black or
white is used for contrast. Transparent containers and arrow labels use the
canvas, not the preset's box fill. Explicit native colour/fill overrides end
the active creation preset and continue to work normally.

The native colour pickers are unchanged. `M-x my/excali-use-preset` and
`M-x my/excali-choose-palette` provide the same actions outside the transient.
Choosing a palette changes available presets only, not colours or defaults.
An applied creation preset keeps its own colour snapshot until another preset
or a native colour/fill override is applied. Browsing palettes does not change
that snapshot or its text-contrast behaviour. This active creation preset is
buffer-local, not saved role metadata: native current-item defaults persist,
but after reopening, reapply a preset to enable its contrast-aware text creation.
Canvas changes remain a separate explicit `my/excali-set-canvas-background`
action; its interactive default is the current Emacs theme's background.

New drawings start with the active theme's palette canvas and Default style.
If that theme has no installed palette, they retain the original one-time
initialization from the theme's default background/foreground, without palette
provenance. Existing native/PNG/SVG scenes retain their saved colours and
defaults. Themes and auto-dark never recolour a drawing or switch its palette.
Palette choices are buffer-local; reopening uses the initial snapshot if
present, otherwise presets require an explicit palette choice.

## Agent use and JSON

Keep `.excalidraw` JSON authoritative. Copy `canvas` to
`appState.viewBackgroundColor`. Map preset `stroke` to `strokeColor`, `fill` to
`backgroundColor`, and use `fillStyle: "solid"` for filled shapes. Set label
elements' `strokeColor` from the paired `text`, checking it against the fill
actually behind the label. Standalone text and arrow labels sit on the canvas.
Do not use a box's text/fill pair blindly for those labels. New-item defaults
can be stored as `appState.currentItemStrokeColor`,
`currentItemBackgroundColor` and `currentItemFillStyle` in native files.

For a new drawing, ask which theme to use if it was not supplied; do not assume
the user's current theme from a palette filename or yesterday's drawing.
The example image-rollout diagram originally used hand-picked fills, not this
generated palette. Its service boxes correspond to Neutral, Mitch's boxes to
Accented, messages/headings to Default, and lifelines/phase boundaries to Muted.
Generated Doric Earth colours intentionally differ from that demo.

New editor-created drawings record this top-level provenance:

```json
"homeConfigPalette": {
  "version": 1,
  "initialTheme": "doric-earth",
  "initialPalette": { "version": 1, "theme": "doric-earth", "canvas": "…", "presets": "…" }
}
```

`initialPalette` contains the complete palette JSON object, not the illustrative
ellipsis above. Agents creating new diagrams should write the same record.
It is an immutable creation snapshot, not a current-role declaration; later
manual edits and palette choices do not update it. Preserve unrelated fields,
including element `customData`. No per-element roles are recorded.

The pinned excali-mode preserves this metadata and native current-item defaults
through save/reopen. **Browser Excalidraw exports discard the top-level metadata
and current-item defaults**, but preserve the painted colours and canvas.
Where the diagrams directory is version-controlled, missing initial provenance
may be recovered from Git history. Do not create commits automatically.

For a requested theme conversion, use the stored palette snapshot as the source
and a generated JSON file as the target. Without roles, equal colours can be
ambiguous: consider element types, fill/stroke combinations and bound-label
relationships, preserve unmatched/explicit colours, and ask about ambiguities.
Review the diff before replacing a drawing. No automatic converter or theme
following is provided.
