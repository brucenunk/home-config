# Excalidraw palettes and workflows

Read `palettes/<theme>.json` before creating or restyling a diagram. These Doric
palettes are generated by the `theme-builder` skill and installed here by the
Emacs module. Ask which theme to use if none was supplied.

## Editor commands

Open a drawing explicitly with `my/excali-open`; ordinary `.excalidraw` visits
edit JSON. In `M-x excali-style`, press **p** for palette presets, or use
`M-x my/excali-use-preset`.

| Preset | Intended use |
| --- | --- |
| Default | Arrows, text and unfilled shapes. |
| Neutral | Ordinary filled boxes. |
| Accented | Highlighted boxes. |
| Muted | Secondary boundaries and lifelines. |
| Red, Green, Yellow, Blue, Magenta, Cyan | Consistently labelled diagram-specific categories. |

Presets style the selection and its bound labels and set defaults for new
ordinary elements. With no selection, only defaults change. Sticky notes are
excluded; use native colour pickers for them. Explicit presets always use the
current Emacs theme. After reopening, reapply a preset to enable contrast-aware
text creation; saved colours alone do not activate that behaviour.
`M-x my/excali-set-canvas-background` changes only the canvas.

### Theme conversion

Opening a scene with usable palette metadata, or enabling an Emacs theme,
converts recognised styling to the current installed palette in every open
drawing, including hidden buffers. Custom/ambiguous colours and sticky notes
are preserved. Scenes without usable metadata and drawings with pending redo
are skipped. **Nothing is saved automatically.** Theme previews can leave
modified drawings even if you return to the original theme.

Avoid theme switching during text entry or another multi-step native edit:
conversion can capture unconfirmed text in undo history.

Use **`M-x my/excali-update-palette`** to choose a palette for one diagram.
Candidates preview as you navigate. `&dark` or `&light` filters theme annotations
with Orderless. `C-g` restores the original scene and history; `RET` accepts one
conversion as a single undo step, including canvas, defaults and saved palette.
The picker does not change the Emacs theme or other drawings. Save normally.

Conversion requires a valid saved `palette`. It preserves custom styling and
reports ambiguous/unsupported matches rather than guessing. Without element
roles, manually chosen colours identical to a preset are indistinguishable
from that preset. Undo/redo restore the palette with the converted content.

### PNG sharing

**`M-x my/excali-export`** exports a disposable Doric Light copy without changing
the source drawing or Emacs theme. A selection exports only that selection;
`C-u` exports the whole diagram. Native scale, padding, background and embedded
scene settings apply. Custom colours remain custom. A usable saved palette and
installed Doric Light palette are required. `C-c C-e` remains native export.

## Org links and publication

For a new drawing, use [the Org drawing workflow](../../docs/emacs-org-excali.md).
For an existing scene, save the Org document, use **`C-c C-l`**, choose `excali`,
and select the file. Links are relative to the document:

```org
#+CAPTION: Image build sequence
[[excali:../diagrams/shared-image-build.excalidraw][Image build]]
```

Follow with `C-c C-o`. Toggle previews with `C-c C-x C-v`; regenerate them with
`M-x org-link-preview-refresh`. Hide a preview to edit its link with `C-c C-l`.
Scene saves refresh displayed references; external edits need explicit refresh
or reopen. Previews render **saved source**, not unsaved drawing-buffer edits.

Previews fit the available text area, with a default cap of 120 frame character
widths (`my/excali-org-preview-width`). Override individual links:

```org
#+ATTR_ORG: :width 90% :align left
[[excali:../diagrams/shared-image-build.excalidraw][Image build]]
```

Integer widths are pixels; percentages use the available text area. Narrower
standalone previews are centred unless overridden. `ATTR_ORG` affects the editor,
not publication. Cached images under `$XDG_CACHE_HOME/excali/` can be deleted;
they regenerate when needed. First rendering is synchronous.

HTML (`C-c C-e h o` / `h h`) and Markdown (`C-c C-e m m`) export use Doric Light,
regardless of the editor theme. Descriptions supply alternative text;
`#+CAPTION` supplies an HTML figure caption or Markdown image title.

- HTML embeds SVGs as data URLs. Other images/resources are not bundled.
  Destinations may strip SVG/data URLs or require separate uploads.
- Markdown writes `{basename}-assets/` beside its output. Share that directory
  with the Markdown file; old assets are not pruned. Buffer/string export places
  assets beside the input Org file. Readers must support SVG and accompanying
  files; captions/sizing depend on the reader.

Other backends, including LaTeX/PDF, fail explicitly. Rendering needs the
configured native excali module/fonts and palette metadata; inline display
also needs SVG support. SVG labels are outlined, not searchable/selectable
text. Export uses saved source and never saves/restyles the authoritative scene.

## Agent-authored JSON

Keep `.excalidraw` JSON authoritative. Use the complete selected palette JSON
object as the top-level `palette` field. Preserve unrelated metadata, including
element `customData`. There are no saved per-element roles.

- Copy `canvas` to `appState.viewBackgroundColor`.
- Map preset `stroke` to `strokeColor`, `fill` to `backgroundColor`, and use
  `fillStyle: "solid"` for filled shapes.
- Use paired `text` for labels, checking contrast against the actual background.
  Standalone text and arrow labels sit on the canvas, not a box fill. Require
  4.5:1 contrast, falling back to black or white when needed.
- Bind labels with both `containerId` and the container's reciprocal
  `boundElements`; positioning text over a box does not bind it.
- For separate label backplates, use rectangles with transparent stroke, solid
  fill and the palette's exact canvas colour. They follow a matching canvas
  conversion; custom canvases/backplates stay custom.
- New-item defaults use `appState.currentItemStrokeColor`,
  `currentItemBackgroundColor` and `currentItemFillStyle`.
- Never make colour the only distinction. Retain descriptive labels or another
  meaningful visual cue.

Check generated diagrams against at least one light and one dark palette on a
disposable copy, including labels, backplates and canvas. Preserve the original
and disclose ambiguous/unconverted styling. For conversion, use the saved
palette as source, preserve unmatched colours, and replace `palette` with the
complete target snapshot. Ask about ambiguities rather than inventing colours.

**Browser Excalidraw exports discard top-level palette metadata and current-item
defaults**, though painted colours remain. Conversion then needs metadata
recovered from history, or individual preset application. Do not commit recovery
automatically. For legacy `homeConfigPalette` files, retain the old current
snapshot (otherwise the initial snapshot) as `palette`; do not repaint colours
merely to migrate metadata.
