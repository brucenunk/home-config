# Machines and the Emacs agent catalogue

`brucenunk.homeManager.machines` is the shared Nix inventory. The `machines`
Home Manager module declares data only; Git, the Emacs catalogue generator, and
the transitional Herdsman generator consume it independently. Consumers import
those features explicitly. Git, Herdsman, and `agent-catalogue` import the
data-only option declarations as a prerequisite; none enables the others.

Hosts own composition. Wampa is composed in `hosts/wampa.nix`; private Woowoo
and Devbox inventories and connection details belong in
`canvanauts/jamesl-home-config`, not this public repository. A private consumer
imports the public modules through its pinned `home-config` input and supplies
its own inventory. No extra user-maintained inventory file is required.

```nix
brucenunk.homeManager.machines = {
  laptop = {
    isLocal = true;
    repositories."example/project" = {
      path = "/Users/example/work/example/project/main";
      defaultBranch = "main";
    };
    models = laptopPiModels;
  };
  builder = {
    directory = "/rpc:builder.example:~/work/";
    repositories."example/project" = {
      path = "/srv/git/project.git";
      defaultBranch = "master";
    };
    models = builderPiModels;
    defaultModel = "provider/vendor/model";
  };
};
```

A non-empty inventory requires exactly one `isLocal = true` record. Other
records default to false. This is host identity for local consumers, **not a
machine selection preference**. Git maintenance uses only that record's
repository paths and retains its native schedules. No remote maintenance is
scheduled. The local record's model default inherits Pi's Nix
`settingsDefaults` when both provider and model are configured. Remote records
do not inherit that local default. Explicit `null` restores first-model
selection; a non-null default must name a configured model.

Repository definitions retain Git's `path` and `defaultBranch` options. Paths
are absolute, machine-local directories accepted by `git -C`, including ordinary
worktrees and bare Git directories; there is no default-checkout requirement.
Herdsman's existing restrictions on linked source workspaces still apply to its
launches. Its TOML and JSON formats and Go consumers are unchanged.

`directory` combines an Emacs connection with the default browsing directory.
The local default is `~/work/`; remote records must specify it explicitly,
preferably using RPC. These values are relative to the Emacs consumer: a
configuration for Emacs on another host must compose its own local/remote
directories. Repository paths never contain a TRAMP prefix.

## Generated Emacs configuration

Import `agent-catalogue` to generate
`$XDG_CONFIG_HOME/emacs/agent-catalogue.el` (normally
`~/.config/emacs/agent-catalogue.el`). This is **trusted executable
configuration**, like the rest of the Nix-managed Emacs configuration—not an
arbitrary data import. It sets `my/agent-machines`, declared and documented by
`my-agent-catalogue.el`. Entries are an alist of string machine names to plists:

```elisp
;; Generated by Nix.
(setq my/agent-machines
      '(("laptop"
         :directory "~/work/"
         :repositories
         ((:name "example/project"
           :path "/Users/example/work/example/project/main"
           :base-ref "origin/main"))
         :default-model "provider/vendor/model"
         :models
         ((:name "provider/vendor/model"
           :thinking-levels ("off" "low" "medium" "high")
           :default-thinking "medium")))))
```

Only repository paths, browsing directories, and projected model capabilities
are emitted—not provider endpoints, credentials, or `isLocal`. `base-ref` is
derived as `origin/${defaultBranch}`. The effective model is the configured
default, otherwise the first model, or an empty string when no models exist.
Thinking defaults to `medium` when supported, otherwise `off`, otherwise an
empty string requiring explicit selection. No mutable Pi settings are read.

`init.el` loads the generated file from `user-emacs-directory` through
`locate-user-emacs-file` once during startup. A missing file is allowed at
startup so unrelated Emacs features and existing notes remain usable; capture
reports missing configuration. Syntax/evaluation errors in this trusted config
are ordinary Emacs load errors, not errors hidden by a data importer.

**Refresh is explicit:** after rebuilding and activating changed inventory,
run `M-x my/agent-catalogue-reload` or restart Emacs. Capture uses the loaded
variable; it no longer rereads disk for every note. Reload clears the old
inventory before loading, so a missing file cannot silently retain old choices.
There are no watchers, timers, or automatic runtime reload hooks.

Structural validation belongs to typed Nix options and generation tests. Lisp
retains checks for missing configuration, empty/unsupported choices, and
unusable model/thinking selections, not a second schema implementation. Nix
rejects oversized model hints, whitespace/control characters, case-insensitive
duplicate references, and inconsistent provider spelling before generation.

Capture always asks for a repository. It selects a sole eligible machine
automatically; multiple eligible machines require an explicit choice with no
default, regardless of which machine runs Emacs. Ordinary capture retains model
and thinking defaults; prefix capture exposes those choices. The machine prompt
also disables Vertico candidate preselection, so Return alone cannot accept the
first machine. Other prompts retain their normal completion behavior. Missing
configuration or unusable required choices prevent note creation. Listing and existing
notes remain independent of the catalogue.

This is configured inventory, not readiness evidence: configuration/capture does not
probe hosts, query Git, create worktrees, or launch sessions. An Emacs session
launcher is future work. Herdsman's existing JSON remains under `herdsman/` for
its own consumers; Emacs no longer reads it.

## Migration and verification

Move `herdsman.machines` to `brucenunk.homeManager.machines`, replace
`herdsman.machineName` with `isLocal = true` on that record, and supply remote
`directory` values. Move local `git.repositories` there too; do not keep a
second inventory. Keep Pi deployment's `models` and the local inventory record
wired to the same Nix value. Herdsman's operational `herdsman.config` stays in
place. Import `agent-catalogue` wherever Emacs capture is used. Removing
Herdsman later does not remove machine options, Git maintenance, or the Emacs
catalogue.

`agent-catalogue-home-manager-module` tests Nix serialization (including quotes,
backslashes, and Unicode), Nix option errors, private-field exclusion, and isolated
configuration loading/reload/capture/list ERT tests. The capture regression runs Vertico's
real candidate update, navigation, and Return command in a headless test buffer;
it is not live UI/runtime-pickup evidence. `git-home-manager-module` checks that only local
repositories participate in maintenance. Herdsman's existing check retains its
JSON/TOML assertions and model-default cases. See [home-manager-checks.md](home-manager-checks.md).

The required Wampa build is isolated verification, not activation or runtime
pickup. Deployment follows [activation.md](activation.md) only when explicitly
requested. Never load feature-worktree Lisp into the shared Emacs daemon; use
isolated batch tests. Later runtime pickup must use the approved deployed files.
